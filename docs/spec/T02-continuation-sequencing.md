# Contract completion sequence — November 6, 2026

The original 105-ticket specification remains authoritative for scope. T02 is a large prefactor, so implementation is split into reviewable slices without falsely closing its parent acceptance.

1. **T02a / issue #7: golden-vector discovery.** New vector families carry a discovered generator/evaluator and named consuming tickets. Existing fixture bytes stay unchanged. Public CLI regressions prove new cases are validated and missing handlers/consumers refuse. This is the current implementation slice.
2. **Additive fields and immutable binding records.** Complete the optional v1 fields, stable section/duration semantics, preregistration/eval/result binding inputs and their consuming-ticket manifest. No concluded evidence changes status yet.
3. **C02 / issue #4: validate concluded sets.** Requires the actual binding schemas from step 2, not closure of the entire T02 umbrella. Bind exact preregistration, set membership, subject revision/host, quotas, thresholds and owner verdicts; synthetic fixture acceptance cannot become owner listening evidence.
4. **Route standing and plan rules.** Only after C02 permits valid conclusions may concluded failure demote routes or change a default pair. Preserve declared/unbenchmarked behavior for absent or inconclusive results.
5. **SongForm assembly, ABC and MIDI.** Separate hand-derived musical vectors, with additive contracts and actual consumer coverage. Preserve instrumental intros/outros, exact note/phrase timing, tempo/meter semantics, section names and source lane restrictions. Unsupported mappings must refuse explicitly rather than silently truncate or retime.
6. **Remaining T02 completeness.** Worker transcripts, declared profiles/job kinds, gate/price snapshots, legacy load checks and full consumer inventory. Close T02 only after every original acceptance condition passes.

## Why the sequence changes

The original T02 scope asks for concluded route-standing behavior, while the later C02 containment follow-up was described as depending on T02. Taking both literally creates a cycle. The prerequisite is the binding schema slice, not T02's entire acceptance. This sequence makes that distinction explicit and never removes C01 merely to produce green tests.

The first product milestone after contracts remains generated contract types (T04), durable ProjectStore/StudioHarness (T05), then the application shell and creator path with synthetic test output. Real model installation, quality judgments and paid inference remain separately gated. A green scaffold, many fixtures or a polished shell alone cannot establish musical quality.
